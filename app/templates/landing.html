What's inside

Design notes for anyone reading the source.

Argon2id password hashing

Accounts use pwdlib with Argon2id and automatic re-hash on login. Sessions ride in signed, HttpOnly cookies via Starlette's SessionMiddleware.

Portable Telegram sessions

Telethon StringSession values live in the database instead of .session files — the app is fully stateless on an ephemeral filesystem.

Pooled connections

One Telethon client per user is pooled in-process with an idle-connection reaper, which is what keeps navigation snappy between requests.

Streamed media

Files stream straight from Telegram to the browser — nothing is buffered on the server or written to disk.

Curated chat list

No full dialog dump. You add chats explicitly by @username or numeric ID, and only those are persisted to your account.

Zero-dependency frontend

One stylesheet, one JS file, an inline SVG sprite. No Tailwind CDN, no external fonts — it renders fine offline and behind a strict CSP.

HTTP API

Typed Pydantic v2 schemas throughout. Full interactive reference at /docs.

Run it yourself

This instance is a public demo of the project. It is non-commercial, has no advertising, and is not affiliated with or endorsed by Telegram. You supply your own Telegram API credentials from my.telegram.org/apps, or use the instance defaults. 

git clone https://github.com/hashemian1382/telegram-web-lite
cd telegram-web-lite

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env    # set SECRET_KEY + Telegram credentials
python -m app.main
